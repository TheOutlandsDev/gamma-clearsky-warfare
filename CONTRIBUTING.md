# Contributing and feedback

Use an issue form for a solo bug, experimental co-op problem, balance observation, or feature idea. Public issues are visible to everyone. Keep reports focused on one reproducible problem.

Include this repository revision, your track, relevant dependency versions, reproducible steps, expected and observed results, and the smallest redacted error excerpt. For co-op, identify host/client roles and whether both content fingerprints matched. Do not post the fingerprints' input files, IPs, tailnet names, real player identities, access keys, complete logs, or campaign saves. Share hardware specifications only to the extent needed for a performance report.

Before testing, back up saves and configs. Change one subsystem at a time. Keep the solo, co-op and AlifeTactics trial tracks distinct. A static check, successful menu load, or open port is not an end-to-end gameplay result.

For code contributions:

1. Explain the trigger and resulting behavior. Add a meaningful regression check where practical.
2. Confirm that you own the contribution or have the necessary redistribution rights. List upstream author, exact source/version, license and modifications for adapted work.
3. Do not submit game assets, mod archives, engine binaries, whole copied upstream overrides, or material of uncertain origin. Even a patch/diff can contain protected code.
4. Original additions are contributed under AGPL-3.0-only unless explicitly agreed and documented otherwise. Preserve third-party notices where applicable.
5. Use a separate test installation; never make a test automatically modify a real game, firewall, network policy, Steam process, or player save.

This is an experimental community test project. Long-campaign balance, co-op synchronization, existing-companion state and complete addon interoperability need gameplay evidence. Please label observations and hypotheses clearly.
